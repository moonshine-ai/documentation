# About the Debug Probe

Q: So what exactly is the Raspberry Pi Debug Probe? What does it do?
A: It's a USB device providing a UART serial port and SWD debug interface.

Q: Does the Debug Probe work on Windows and Mac, or just Linux?
A: It works on Windows, macOS, and Linux platforms without GPIO headers.

Q: I've heard about CMSIS-DAP — is the Debug Probe compatible with that?
A: Yes, it's compatible with the CMSIS-DAP standard and works with OpenOCD.

Q: Can I update the firmware on the Debug Probe if I need to?
A: Yes, the firmware is open source and easily upgradeable.

# The Debug Probe

Q: What voltage does the Debug Probe run at? I don't want to fry anything.
A: The probe operates at 3.3V nominal I/O voltage.

Q: What cables actually come in the box with the Debug Probe?
A: A USB power cable and three debug cables with JST-SH connectors are included.

Q: What are the wire colors on the debug cables and what do they mean?
A: Orange is TX/SC output, black is GND, and yellow is RX/SD input.

Q: How many LEDs does the Debug Probe have and what are they for?
A: It has five LEDs: one red power LED and four activity indicator LEDs.

Q: What do the DAP LEDs do when I connect to a target with OpenOCD?
A: OpenOCD switches both DAP LEDs on when connected, off on disconnect.

Q: I'm connecting the probe to something that has its own power supply. Do I need to be careful about anything?
A: Connect GND first before any signal lines to avoid damaging the probe.

# Getting started

Q: I've got a Pico H — how do I wire it up to the Debug Probe?
A: Connect the D port to the SWD JST-SH connector and U port for UART.

Q: My Pico doesn't have the JST-SH connector. Can I still use the Debug Probe with it?
A: Yes, solder a male connector to SWCLK, GND, and SWDIO header pins instead.

Q: For the UART connection on the Pico H, does RX go to RX and TX go to TX?
A: No, Debug Probe RX connects to Pico TX, and TX connects to Pico RX.

# Install tools

Q: What tools do I actually need to install to use the Debug Probe?
A: You need OpenOCD and GDB; an IDE may also be useful.

Q: Is there an easy way to get everything installed at once rather than doing it manually?
A: Install the VS Code extension, which bundles OpenOCD, toolchains, GDB, and register definitions.

Q: Can I manually install the tools on Windows if I want to?
A: Manual installation on Windows is not recommended.

# Starting a Debug Session

Q: Do I have to unplug my Pico and hold BOOTSEL every time I want to upload new code with the Debug Probe?
A: No, the Debug Probe uploads binaries via SWD completely hands-free.

Q: What file format do I use when uploading through the Debug Probe? Is it the UF2 file?
A: No, use the ELF file, not the UF2 file used for drag-and-drop.

Q: What's the command to upload a binary using OpenOCD with the Debug Probe?
A: Use openocd with cmsis-dap.cfg, rp2040.cfg, adapter speed 5000, and program command.

Q: I want to use breakpoints while debugging. Do I need to build my code differently?
A: Yes, build as Debug type, not Release, to get full debugger information.

Q: I'm on a Mac and I need GDB for Arm. Which one should I use?
A: Use arm-none-eabi-gdb from the Arm GNU toolchain downloads website.

Q: How do I actually attach GDB to the OpenOCD server once it's running?
A: Start GDB with your ELF file, then run target remote localhost:3333.

# Serial connections

Q: What pins on the Pico do I connect the Debug Probe's UART to?
A: Connect to physical pins 3 GND, 1 UART0_TX on GP0, and 2 UART0_RX on GP1.

Q: Once I've connected everything, how does the serial port show up on my computer?
A: On Raspberry Pi it's /dev/ttyACM0; on macOS it appears as /dev/cu.usbmodemXXXX.

Q: What program do I use to actually read the serial output from my Pico?
A: Install minicom and open the port with minicom -b 115200 -o -D /dev/ttyACM0.

Q: How do I quit minicom once I've opened it? I can't figure it out.
A: Press CTRL-A followed by X to exit minicom.

Q: Is there a simple test program I can run to check that serial communication is working?
A: Yes, build and upload the Hello World example; you should see "Hello, world!" printed.

# Updating the firmware on the Debug Probe

Q: How do I know what firmware version my Debug Probe is running?
A: Run lsusb -v -d 2e8a:000c and grep for bcdDevice to check the version.

Q: What's the latest firmware version for the Debug Probe?
A: The latest version is 2.2.3.

Q: How do I actually update the firmware on my Debug Probe?
A: Hold BOOTSEL while plugging in, copy debugprobe.uf2 to the RPI-RP2 volume.

Q: OpenOCD says my firmware version is 2.0.0 but I thought I updated it. What's going on?
A: That line refers to the CMSIS-DAP protocol level, not the Debug Probe firmware version.

# Schematics

Q: Are there schematics available if I want to look at how the Debug Probe is built?
A: Yes, schematics and a mechanical drawing are available as downloadable PDFs.

# Whole Document

Q: What even is the Debug Probe — do I need one or can I just use my regular Pi?
A: It lets platforms without GPIO headers connect to Pico's UART and SWD port.

Q: I've got a Pico and I want to debug my code properly. Where do I even start?
A: Get the Debug Probe, install the VS Code extension, and see the Getting Started guide.

Q: Can I use the Debug Probe just for serial output without doing the full SWD debug thing?
A: Yes, it has a separate UART bridge you can use independently via its U port.
