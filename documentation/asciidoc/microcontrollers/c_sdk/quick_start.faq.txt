# Quick-start your own project

Q: I'm on Linux and want to start a Pico C project. What do I need to install first?
A: Install CMake version 3.13 or higher and the GCC ARM cross compiler.

Q: How do I get the Pico SDK onto my computer?
A: Clone it from GitHub at github.com/raspberrypi/pico-sdk.

Q: I don't know where to put the PICO_SDK_PATH thing. What are my options?
A: Set it as an environment variable or pass it directly to the cmake command.

Q: What's the bare minimum C code I need to get a hello world running on the Pico?
A: Include pico/stdlib.h, call setup_default_uart, then printf your message.

Q: I want my program to print over USB instead of the UART. How do I do that?
A: Check the hello-usb example, which shows how to use USB for stdout.

Q: After I've written my code, how do I actually build it?
A: Create a build directory, run cmake inside it, then run make hello_world.

Q: What files do I get after building, and what are they for?
A: You get a dot-elf for debugging and a dot-uf2 for drag-and-drop installation.

Q: I've got a Pico W, not a regular Pico. Do I need to do anything different when building?
A: Pass minus DPICO_BOARD equals pico_w to cmake to enable wireless and correct settings.

Q: How does passing the board name to cmake actually help? What does it change?
A: It sets compiler defines like pin numbers and enables board-specific libraries like wireless.

Q: Where can I find a list of all the boards the SDK supports?
A: Check the boards include directory in the pico-sdk GitHub repository.

Q: These instructions feel pretty brief. Is there somewhere I can get more detailed help?
A: The Getting Started and Pico C/C++ SDK books have detailed steps for multiple platforms.

Q: What's pico_add_extra_outputs doing in the CMakeLists file?
A: It creates additional output formats like map, bin, hex, and uf2 files alongside the ELF.
