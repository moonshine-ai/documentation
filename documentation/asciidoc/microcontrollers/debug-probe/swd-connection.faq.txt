# Starting a Debug Session

Q: Do I have to unplug my Pico every time I want to upload new code with the Debug Probe?
A: No, the Debug Probe lets you upload binaries hands-off via SWD.

Q: What's the recommended way to upload and debug programs on my Pico?
A: Use the Raspberry Pi Pico VSCode extension, which integrates OpenOCD and GDB.

Q: I don't want to use VSCode, can I just upload code from the command line?
A: Yes, use OpenOCD directly with the cmsis-dap and rp2040 config files.

# Standalone program upload

Q: What file do I use when uploading with the Debug Probe, the UF2 or something else?
A: Use the ELF file, not the UF2 file used for drag-and-drop.

Q: I keep trying to upload my UF2 file with OpenOCD and it's not working. What am I doing wrong?
A: OpenOCD needs the ELF version of the file, not the UF2 file.

Q: What's the actual command to push a binary to my Pico using the Debug Probe?
A: Run sudo openocd with cmsis-dap.cfg, rp2040.cfg, adapter speed, and program options.

# Standalone debug session

Q: I want breakpoints and stepping through code on my Pico. How do I set that up?
A: Run OpenOCD in server mode, then connect GDB for breakpoints and single-step debugging.

Q: My debugger isn't giving me much useful information. What am I missing?
A: You must build as Debug type, not Release, to get full debugger information.

Q: I'm on a Mac and trying to debug my Pico. What version of GDB do I need?
A: Use arm-none-eabi-gdb from the Arm GNU Toolchain on Arm's website.

Q: What GDB command do I use if I'm on Linux but not on a Raspberry Pi?
A: Use gdb-multiarch on Linux devices that aren't Raspberry Pis.

Q: How do I actually connect GDB to my Pico once OpenOCD is running?
A: Open a second terminal, run GDB on your ELF file, then target remote localhost:3333.

Q: Do I need two terminal windows open to do debugging?
A: Yes, one runs the OpenOCD server and one runs the GDB debugger.
