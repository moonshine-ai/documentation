# Conditional filters

Q: I've got one SD card I use in different Pis and monitors. Can config.txt handle that somehow?
A: Yes, conditional filters let one config.txt apply different settings per hardware.

Q: What even are conditional filters and why would I need them?
A: They let a single config.txt create different configurations for different hardware combinations.

# The `[all]` filter

Q: What does putting `[all]` at the end of my config file actually do?
A: It resets all previously set filters so settings apply to all hardware again.

Q: I keep accidentally mixing up my filter settings. Is there a way to stop that?
A: Add an `[all]` filter at the end of filtered sections to avoid unintentionally combining filters.

# Model filters

Q: I want different settings just for my Pi 4. What do I put in config.txt?
A: Use the `[pi4]` filter; it applies to 4B, 400, Compute Module 4, and Compute Module 4S.

Q: Does the Pi 400 use the pi4 filter settings or does it have its own?
A: Pi400 has its own `[pi400]` filter but also reads `[pi4]` contents too.

Q: I've got a Compute Module 5. Which filters does it pick up?
A: It reads both `[cm5]` and `[pi5]` filter contents.

Q: Can I target just one specific Pi model and not have it bleed into related ones?
A: Use `board-type` filter with a revision code to target exactly one specific model.

Q: Why would I even need different model filters? What are they useful for?
A: They're useful for different kernels, initramfs images, or overclocking settings per model.

Q: Zero 2 W — does it read multiple filters or just its own?
A: It reads `[pi02]`, `[pi0w]`, and `[pi0]` filter contents.

# The `[none]` filter

Q: I've got some settings I don't want active but don't want to delete. What can I do?
A: Use the `[none]` filter to keep unused settings in config.txt without commenting every line.

Q: What does the none filter actually do to the settings under it?
A: It prevents any settings that follow from being applied to any hardware.

# The expression filter

Q: What's the expression filter for? I've never heard of it before.
A: It's for comparing boot variables to constants, intended to support OTA updates, debug, and test.

Q: What boot variables can I use in an expression filter?
A: You can use boot_arg1, cust_otpN, bootvar0, boot_count, boot_partition, and partition.

Q: Can I do assignments inside an expression filter condition?
A: No, expression filters have no side-effects, so assignment operators aren't supported.

# `boot_arg1`

Q: I want to pass a value across a reboot. Is there a way to do that?
A: Yes, boot_arg1 is a 32-bit reset-safe register for passing parameters across reboots.

Q: If I set boot_arg1 in config.txt, does it take effect right away?
A: No, set_reboot_arg1 sets the value for next boot, not the current boot's value.

Q: Where can I read what boot_arg1 was when the OS started?
A: Read it from device-tree at `/proc/device-tree/chosen/bootloader/arg1`.

# `cust_otpN`

Q: Can I have different configs based on something permanently stored on the board?
A: Yes, cust_otpN lets you pick configurations based on values stored in customer OTP rows.

Q: How many customer OTP rows can I use with the cust_otp filter?
A: There are eight rows, with N ranging from 0 to 7.

# `bootvar0`

Q: I want the same SD card image to behave differently on different boards. Can I do that?
A: Yes, set bootvar0 via rpi-eeprom-config and use it as a conditional in config.txt.

Q: Which Pis support the bootvar0 variable?
A: It's available on Raspberry Pi 4 and newer devices only.

# `boot_count`

Q: Does the boot count reset if I pull the power?
A: Yes, boot_count is cleared if power is disconnected.

Q: What happens when boot_count hits 256?
A: It wraps back to zero at 256.

Q: Which Pis support boot_count?
A: Only Raspberry Pi 5 and newer devices support boot_count.

# `boot_partition`

Q: I'm doing A/B booting. Can I load different cmdline files based on which partition booted?
A: Yes, use boot_partition filter to load different cmdline files per partition.

Q: Can the boot_partition value end up different from the partition I actually requested?
A: Yes, if autoboot.txt overrides it or PARTITION_WALK kicks in for non-bootable partitions.

# The `[tryboot]` filter

Q: What's the tryboot filter actually for?
A: It's for selecting a different boot partition in tryboot mode for fail-safe OS updates.

# The `[EDID=*]` filter

Q: I've got two monitors and one Pi. Can config.txt automatically use different settings for each?
A: Yes, the EDID filter lets you apply settings based on which specific monitor is connected.

Q: How do I figure out the EDID name of my monitor so I can use it in the filter?
A: Run edid-decode against the edid file in /sys/class/drm, then combine Manufacturer and Display Product Name.

Q: I just connected a different monitor after booting. Will the EDID filter pick it up?
A: No, hotplugging after boot won't apply different settings; the monitor must be connected at boot.

Q: Does the EDID filter work on the Pi 5?
A: No, the EDID filter is not available on Raspberry Pi 5.

Q: I've got both HDMI ports in use on my Pi 4. Does the EDID filter check both?
A: Yes, on Pi 4 the EDID filter checks both HDMI ports and applies all matching configurations.

# The serial number filter

Q: I want certain settings to only apply to one specific Pi, not any other board. How do I do that?
A: Use the serial number filter with your Pi's last eight hex digits from /proc/cpuinfo.

Q: How do I find my Pi's serial number?
A: Run `cat /proc/cpuinfo` and use the last eight hex digits shown near the bottom.

Q: My Pi shows more than eight hex digits in the serial field. Which part do I use?
A: Only use the last eight hex digits, even if earlier digits contain non-zero values.

# The GPIO filter

Q: Can I make config settings depend on whether a GPIO pin is high or low?
A: Yes, use `[gpio4=1]` or `[gpio2=0]` style filters to apply settings based on GPIO state.

# Combine conditional filters

Q: Can I stack multiple filters together, like model and monitor at the same time?
A: Yes, list different filter types one after another and they combine together.

Q: What happens if I put two model filters in a row, like pi1 then pi2?
A: Filters of the same type replace each other, so pi2 overrides pi1.

Q: I accidentally combined filters I didn't mean to. How do I reset back to normal?
A: Use the `[all]` filter to reset all previous filters and start fresh.
