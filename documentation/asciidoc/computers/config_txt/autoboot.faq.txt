# `autoboot.txt`

Q: What's autoboot.txt and do I actually need it?
A: It's optional and specifies the boot partition number for your Pi.

Q: Can I use autoboot.txt to do like a safe OS update where I can roll back if it breaks?
A: Yes, use it with the tryboot feature to implement A/B booting for upgrades.

Q: How big can autoboot.txt be? Is there a limit?
A: Yes, autoboot.txt is limited to 512 bytes in size.

Q: What kind of filters does autoboot.txt support?
A: It supports the all, none, and tryboot conditional filters.

# `boot_partition`

Q: How do I tell the Pi which partition to boot from?
A: Set the boot_partition number in autoboot.txt to your desired partition.

Q: What happens if I pass a partition number to the reboot command directly?
A: The reboot command's partition number takes priority over autoboot.txt's setting.

Q: Do partition numbers start at zero or one?
A: Partition numbers start at one, with MBR partitions numbered one through four.

Q: What does it mean if I set boot_partition to zero?
A: Partition zero means boot from the default first bootable FAT partition.

Q: What format does a partition need to be in to actually be bootable?
A: Partitions must be FAT12, FAT16, or FAT32 and contain a start.elf file.

Q: My Pi 5 doesn't have a start.elf file. Does that mean my partition isn't bootable?
A: On Raspberry Pi 5, a config.txt file makes a partition bootable instead.

# The `[tryboot]` filter

Q: How do I actually boot into tryboot mode?
A: Run sudo reboot "0 tryboot" from the terminal to boot in tryboot mode.

Q: When does the tryboot filter activate?
A: The tryboot filter passes only when the system booted with the tryboot flag set.

# `tryboot_a_b`

Q: What does setting tryboot_a_b to one actually do?
A: It loads normal config.txt and boot.img instead of tryboot.txt and tryboot.img.

Q: I don't want to modify config files inside each partition for A/B switching. Is there another way?
A: Yes, set tryboot_a_b to one to switch at partition level without editing partition files.

# Example update flow for A/B booting

Q: Can you walk me through how A/B booting actually works with tryboot?
A: System boots partition two normally, downloads update to partition three, then tests via tryboot reboot.

Q: So after a successful update, what changes in autoboot.txt?
A: The boot_partition values swap so partition three becomes the new default boot partition.

Q: What happens if the update fails? Does it just stay on the old partition?
A: Yes, tryboot flag clears automatically and partition two remains the default boot partition.

Q: Do I have to reboot after editing autoboot.txt to commit an update?
A: No, rebooting after updating autoboot.txt is not mandatory.

Q: Is there anything I need to be careful about if I don't reboot after updating autoboot.txt?
A: Avoid overwriting the current partition since autoboot.txt already committed the last update.

Q: How does the update service know whether tryboot is actually active?
A: Check /proc/device-tree/chosen/bootloader/tryboot equals one to confirm tryboot is active.

# Whole Document

Q: I've never heard of tryboot before. What's the basic idea behind it?
A: Tryboot lets you test a new OS partition and roll back automatically if it fails.

Q: Can I combine autoboot.txt with other Pi config stuff or does it work on its own?
A: It works alongside conditional filters like all, none, and tryboot within autoboot.txt.

Q: What's the difference between tryboot.txt and config.txt when using A/B booting?
A: With tryboot_a_b set to one, normal config.txt loads even when tryboot flag is active.
