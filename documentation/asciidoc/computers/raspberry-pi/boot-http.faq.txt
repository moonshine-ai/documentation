# HTTP boot

Q: What is HTTP boot on the Raspberry Pi and what's it actually used for?
A: HTTP boot downloads files over Ethernet to boot Raspberry Pi Imager.

Q: Can I still use HTTP boot even if I've turned off network install at startup?
A: Yes, HTTP boot works even when network install on boot is disabled.

Q: I want my Pi to fall back to booting over the network if other options fail. Can I do that?
A: Yes, add HTTP boot as a fallback method in your BOOT_ORDER settings.

Q: What files actually get downloaded when HTTP boot runs?
A: It downloads boot.img and boot.sig from the configured HTTP host.

Q: What even is boot.img? Like, what's inside it?
A: It's a RAM disk containing a boot file system.

Q: I've got secure boot enabled but HTTP boot isn't working. What's going on?
A: HTTP boot is ignored if secure boot is on and HTTP_HOST isn't set.

# Requirements

Q: What do I need to update to before HTTP boot will work?
A: Update to a bootloader released 10th March 2022 or later.

Q: Can I use HTTP boot over Wi-Fi?
A: No, HTTP boot requires a wired Ethernet connection.

Q: I want to use my own SSL certificates with HTTP boot. Does my Pi support that?
A: Only devices running the BCM2712 CPU support custom CA certificates.

Q: How old does my bootloader need to be before custom certificates stop working?
A: You need a bootloader released 5th April 2024 or later for custom CA certificates.

# Keys

Q: Do I need to sign the files I'm serving for HTTP boot, or can I just put them on a web server?
A: All HTTP downloads must be signed; unsigned files won't work.

Q: I'm hosting my own network install image. How do I add my public key to the EEPROM?
A: Run rpi-eeprom-config with your boot.conf and public key PEM file.

Q: If I update the EEPROM firmware later, do I lose my custom key?
A: Yes, a public EEPROM update removes your key and you'll need to re-add it.

Q: How do I sign my own network install image with my private key?
A: Use rpi-eeprom-digest with your boot.img and private key PEM file.

Q: Where do I put boot.img and boot.sig once I've signed them?
A: Put both files on your web server to serve your signed network install image.

# Certificates

Q: Does network install use plain HTTP or something more secure when downloading?
A: Network Install uses HTTPS to download OS images from the Raspberry Pi website.

Q: I want to serve my own OS images securely. Can I add my own certificate to the Pi?
A: Yes, add a custom CA certificate to your device EEPROM using rpi-eeprom-config.

Q: How do I turn my PEM certificate into the format the Pi needs for EEPROM?
A: Use openssl x509 to convert your PEM file to DER-encoded format.

Q: What's the HTTP_CACERT_HASH setting for? Do I really need it?
A: It tells Network Install to use HTTPS port 443 instead of HTTP port 80.

Q: How do I check that my Pi is actually using HTTPS during network boot and not plain HTTP?
A: Check the boot output for GET request URLs showing https and port 443.

# Secure boot

Q: I've got secure boot turned on. Can I still use network install?
A: Yes, but you must sign boot.img and host it yourself with your own key.

Q: What happens to HTTP boot if secure boot is on but I haven't set HTTP_HOST?
A: Both network install and HTTP boot get disabled if HTTP_HOST isn't set.
