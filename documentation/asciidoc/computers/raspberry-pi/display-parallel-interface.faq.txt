# Display Parallel Interface (DPI)

Q: What's DPI and why would I use it instead of HDMI on my Raspberry Pi?
A: DPI lets you connect parallel RGB displays via the 40-pin GPIO connector.

Q: Does my Raspberry Pi even support DPI displays or do I need special hardware?
A: All Raspberry Pi boards with a 40-pin header and Compute Modules support DPI.

Q: How many bits of color can a DPI display do on the Pi?
A: DPI supports up to 24-bit parallel RGB, with 565, 666, or 888 modes available.

Q: Who controls the DPI interface, like is it software or hardware?
A: The GPU firmware controls it, configured via config.txt and a Linux Device Tree overlay.

# GPIO pins

Q: Which GPIO pin is the pixel clock for DPI?
A: GPIO0 handles the PCLK pixel clock function in DPI alternate function two.

Q: What alternate function number do I need to set for DPI on the GPIO bank?
A: DPI is available as alternate function two, called ALT2, on GPIO Bank 0.

Q: How many GPIO pins does DPI actually use up? That seems like a lot.
A: DPI can use up to 28 pins, from GPIO0 through GPIO27, for full 24-bit color.

Q: I want to use RGB565 mode. Which GPIOs carry the color data?
A: In 565 mode depending on sub-mode, color data spans roughly GPIO4 through GPIO19.

# Disable other GPIO peripherals

Q: I've got I2C enabled on my Pi and I want to add a DPI display. Will that cause problems?
A: Yes, conflicting GPIO peripherals like I2C and SPI must be disabled in config.txt.

Q: How do I turn off SPI and I2C so they don't clash with my DPI display?
A: Set dtparam=i2c_arm=off and dtparam=spi=off in your config.txt file.

# Configure a display

Q: Do I have to manually set up a DPI display or does the Pi figure it out on its own?
A: Auto detect is enabled by default and KMS configures settings automatically if supported.

Q: How do I turn auto detect back on if I accidentally disabled it?
A: Add display_auto_detect=1 to your config.txt to re-enable auto detection.

Q: I've got a third-party DPI display, not the official one. How do I get it working?
A: You must add a dtoverlay entry in config.txt using the manufacturer's provided overlay.

Q: My display doesn't have a kernel overlay. Am I just stuck or is there another way?
A: Use the panel-dpi driver to manually define display timings as device tree parameters.

Q: I keep getting errors because my device tree line is too long. What do I do?
A: Split the parameter assignment across multiple lines; device tree lines can't exceed 80 characters.

Q: What's the parameter I need to set the display's clock speed in the device tree?
A: Use the clock-frequency parameter to set display clock frequency in hertz.

Q: Can I control the backlight of my DPI display through the Pi's GPIO?
A: Yes, use the backlight-gpio parameter to define a GPIO pin for backlight control.

Q: I'm switching to RGB888 mode. Which GPIOs does that use?
A: RGB888 uses GPIOs 0 through 27 for full 24-bit color output.

Q: What happened to dpi_output_format and dpi_timings in config.txt? They don't seem to work anymore.
A: In Raspberry Pi OS Bookworm and later, they're superseded by the vc4-kms-dpi-generic overlay.

# Whole Document

Q: I want to hook up a cheap parallel LCD to my Raspberry Pi. Is that actually possible?
A: Yes, parallel RGB displays connect via the 40-pin GPIO using the DPI interface.

Q: What's the difference between using DSI, HDMI, and DPI for a display on the Pi?
A: DPI uses the GPIO pins; DSI and HDMI are dedicated ports; all are separate interfaces.

Q: I'm totally new to this. Do I need to edit config.txt to get a DPI display working?
A: Yes, you need config.txt entries for the overlay and possibly timings to configure DPI.
