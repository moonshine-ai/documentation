# EEPROM Boot Flow

Q: What's different about how the Pi 4 boots compared to older Pis?
A: Pi 4 loads the second-stage bootloader from SPI flash EEPROM instead of bootcode.bin.

Q: What even is the EEPROM bootloader and which Pis use it?
A: Raspberry Pi 4 and newer flagship devices use an EEPROM-based bootloader system.

# First Stage Bootloader

Q: What's the very first thing that happens when my Pi powers on?
A: The SoC powers up and reads OTP to check if the nRPIBOOT GPIO is configured.

Q: What does recovery.bin actually do? I keep seeing it mentioned.
A: It's a minimal second-stage program used to reflash the bootloader SPI EEPROM image.

Q: If the Pi can't find the second stage bootloader on the EEPROM, what happens?
A: It repeatedly attempts to load recovery.bin from USB device boot, retrying on failure.

Q: When does the Pi try to load recovery.bin from the SD card?
A: When SD recovery is enabled in OTP and nRPIBOOT GPIO is high or unconfigured.

# Second Stage Bootloader

Q: Where does the Pi look for boot order instructions?
A: It reads the BOOT_ORDER parameter from the EEPROM configuration file each boot cycle.

Q: My Pi won't boot and it's just flashing an error pattern on the LED. What does that mean?
A: The STOP boot mode triggers a "start.elf not found" LED error pattern and halts forever.

Q: How does network booting work on the Pi? Like what protocol does it use?
A: It uses DHCP to get an IP address, then loads firmware from a TFTP server.

Q: Can my Pi boot from an NVMe drive?
A: Yes, it scans PCIe for an NVMe device and attempts to load firmware from it.

Q: What happens if RPIBOOT mode is selected but nothing connects over USB?
A: RPIBOOT has no timeout, so it waits indefinitely for a USB OTG connection.

Q: I want my Pi to just keep cycling through boot options. How do I set that up?
A: Set RESTART in BOOT_ORDER to jump back to the first boot mode and retry everything.

# Differences on Raspberry Pi 5

Q: On the Pi 5, how do I wake it up from sleep instead of using GPIO 3?
A: Press the power button to wake the Pi 5 from PMIC STANDBY or HALT states.

Q: Does the Pi 5 still need start.elf like older models do?
A: No, the Pi 5 firmware loads the Linux kernel directly; start.elf is embedded in the bootloader.

Q: My Pi 5 isn't booting from USB and it's connected to a 3A power supply. What's going on?
A: USB boot is disabled by default on 3A supplies; enable usb_max_current_enable=1 in config.txt.

Q: Can I just press the power button to get USB boot working on the Pi 5 temporarily?
A: Yes, pressing the power button once on a failed USB boot temporarily enables USB booting.

# Bootloader Updates

Q: Can the bootloader update itself during the boot process?
A: Yes, if a pieeprom.upd file is found, the bootloader updates before firmware starts.

# Fail-Safe OS Updates (tryboot)

Q: I want to test an OS update but be able to roll back if it breaks things. Is there a way to do that?
A: Yes, use tryboot to load tryboot.txt with update settings; a crash reverts to config.txt automatically.

Q: How do I actually trigger tryboot? What's the command?
A: Run sudo reboot '0 tryboot' — you must quote the argument as reboot only accepts one.

Q: Does tryboot work on all Pi models?
A: Yes, all Raspberry Pi models support tryboot, with a minor EEPROM caveat on Pi 4B 1.0 and 1.1.

Q: What's different about tryboot when secure boot is turned on?
A: With secure-boot enabled, tryboot loads tryboot.img instead of the usual boot.img.

# tryboot_a_b Mode

Q: What does the tryboot_a_b setting actually do?
A: When set to 1, it loads config.txt instead of tryboot.txt, since partition switching already happened.

Q: Is tryboot_a_b ever turned on automatically without me setting it?
A: Yes, it's implicitly set to 1 when loading files from inside a boot.img ramdisk.
