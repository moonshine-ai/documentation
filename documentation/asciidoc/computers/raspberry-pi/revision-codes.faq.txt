# Raspberry Pi revision codes

Q: How do I find out what revision my Raspberry Pi is?
A: Run cat /proc/cpuinfo and check the Revision line at the bottom.

Q: I ran that cpuinfo command and I see BCM2835 listed as the hardware but I've got a Pi 4. Is that right?
A: Yes, all Raspberry Pis report BCM2835 regardless of their actual processor.

Q: I don't want to use cpuinfo to check my Pi model, is there another way?
A: You can run cat /sys/firmware/devicetree/base/model instead.

# Old-style revision codes

Q: I've got an old Pi and its revision code is 0004. What model is that?
A: That's a Raspberry Pi Model B revision 2.0 made by Sony UK.

Q: My Pi's revision code is 0002 — how much RAM does it have?
A: Revision code 0002 is a Model B with 256 MB of RAM.

Q: What's the highest revision code in the old system before they switched to the new style?
A: The old-style sequential revision codes went up to 0015.

# New-style revision codes

Q: What does the warranty bit in the revision code actually mean?
A: It's set to 1 if the warranty's been voided by overclocking.

Q: I heard overclocking voids the warranty — does that show up in the revision code somewhere?
A: Yes, bit 25 is the warranty bit and gets set to 1 if you've overclocked.

Q: Does the warranty bit thing apply to the Pi 4 too?
A: No, the warranty bit is never set on Raspberry Pi 4.

Q: How can I tell from the revision code how much RAM my Pi has?
A: Bits 20 to 22 encode memory size, from 256 MB up to 16 GB.

Q: I want to know which manufacturer made my Pi. Where's that in the revision code?
A: The manufacturer is encoded in bits 16 to 19 of the new-style revision code.

Q: How do I know if a revision code is new-style or old-style?
A: Check bit 23, the New flag — it's 1 for new-style and 0 for old-style.

Q: What processor types are encoded in the new revision code format?
A: The processor field covers BCM2835, BCM2836, BCM2837, BCM2711, and BCM2712.

# New-style revision codes in use

Q: What's the revision code for a Raspberry Pi 4B with 4 gigs of RAM made by Sony?
A: A Pi 4B with 4 GB from Sony UK has revision codes c03111 through c03115.

Q: I've got code d04170 — what Pi is that?
A: That's a Raspberry Pi 5 revision 1.0 with 8 GB of RAM from Sony UK.

Q: Is this revision code list totally complete for every board ever made?
A: No, the list isn't exhaustive — there may be codes in use not listed there.

# Using revision codes for board identification

Q: I've got revision code c03111 — how do I figure out what model that is by hand?
A: Convert to binary, then decode each section using the bit field table.

Q: How do I pull just the revision code from the command line without all the other cpuinfo stuff?
A: Use cat /proc/cpuinfo piped to grep Revision to get just that line.

Q: I'm writing a C program and want to check if I'm on a Pi 4B with at least 2 gigs. How do I do that?
A: Use bit shifts to extract the new flag, model, and memory fields from the revision code.

Q: Can I do that revision code check in Python too?
A: Yes, the same bit shift approach works in Python using subprocess to read cpuinfo.

# Best practices for revision code usage

Q: Is it okay to just check for specific revision codes like c03111 in my program?
A: No, that breaks when new board revisions or production locations create new codes.

Q: So what's the right way to check what Pi model I'm dealing with in code?
A: Filter by the board-type field or memory amount field instead of the full revision code.

Q: Why does filtering by exact revision code cause problems?
A: New revisions and manufacturing location changes each create new codes not in your list.

Q: I always need to check if it's a new-style revision code before checking other fields, right?
A: Yes, always check bit 23, the New flag, before checking any other fields.

# Check Raspberry Pi model and CPU across distributions

Q: I'm not running Raspberry Pi OS — is there a way to check the model that works everywhere?
A: Check the device tree using cat /proc/device-tree/compatible on any Linux distribution.

Q: What does that device tree command actually output? I don't know what to expect.
A: It outputs two null-separated strings with comma-separated make and model values.

Q: What's the device tree model string for a Raspberry Pi 5?
A: The Raspberry Pi 5 outputs raspberrypi as make and 5-model-b as the board model.

Q: I want to check my Pi's CPU using the device tree. What chip does the Pi 5 use?
A: The Raspberry Pi 5 uses a bcm2712 CPU made by brcm according to the device tree.

Q: What's the CPU for a Raspberry Pi Zero W according to the device tree?
A: The Raspberry Pi Zero W uses a BCM2835 processor made by brcm.

# Whole Document

Q: I just want to know what Pi I have. What's the easiest way to check?
A: Run cat /proc/cpuinfo and look at the Revision and Hardware lines at the bottom.

Q: My cpuinfo doesn't have a Hardware line — is something wrong?
A: No, depending on your kernel, cpuinfo may or may not include the Hardware line.

Q: What's the difference between old-style and new-style revision codes?
A: Old codes were sequential hex numbers; new codes encode model, RAM, and manufacturer in specific bits.

Q: I've got a really old Pi — will it have a new-style or old-style revision code?
A: Early Pi models used old-style sequential codes from 0002 to 0015.
