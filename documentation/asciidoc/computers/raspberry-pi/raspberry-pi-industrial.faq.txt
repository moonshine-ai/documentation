# Industrial use of the Raspberry Pi

Q: What's OTP memory and why would I need it for my Raspberry Pi project?
A: OTP memory stores one-time programmable settings permanently in the Pi's chip.

Q: I'm building a product using a Raspberry Pi. What extra features are available for that kind of use?
A: There are OTP settings, private key storage, and customer MAC address options.

# One-time programmable settings

Q: How do I see all the OTP values on my Raspberry Pi?
A: Run the command `vcgencmd otp_dump` to list all OTP values.

Q: What info is stored in those OTP rows like 28 and 29?
A: Rows 28, 29, and 30 store serial number, its complement, and board revision.

Q: How many OTP rows are available for customers to use?
A: Eight rows of 32 bits each, rows 36 to 43, are available for customers.

Q: Wait, do the OTP row numbers change depending on which Pi I have?
A: Yes, BCM2712 devices use different row numbers for serial and customer data.

Q: What's vcmailbox and do I need it to program OTP rows?
A: vcmailbox is a Linux driver interface used to program OTP rows via firmware.

# Write and read customer OTP values

Q: I want to write a value to a customer OTP row. How do I actually do that?
A: Use the `SET_CUSTOMER_OTP` tag with vcmailbox, specifying start row, count, and values.

Q: Can I write to multiple OTP rows at once or do I have to do them one at a time?
A: You can write multiple rows at once by specifying the number and values together.

Q: How do I check what's currently stored in my customer OTP rows?
A: Use vcmailbox with tag `0x00030021`, specifying start row, count, and placeholder zeros.

Q: Wait, if I write the wrong thing to OTP, can I fix it?
A: No, OTP bits changed from 0 to 1 can never be changed back.

# Locking OTP on non-BCM2712 devices

Q: Can I lock the OTP so nobody can change it later?
A: Yes, use a special vcmailbox argument to lock OTP, but it's irreversible.

Q: If I lock OTP, is that permanent or can I unlock it later?
A: The locking operation is irreversible and the values can never be altered again.

# Locking OTP on BCM2712 devices

Q: Does locking OTP work differently on a BCM2712 Pi?
A: Yes, BCM2712 OTP locks only last until the device resets, needing reapplication each boot.

Q: I locked OTP on my BCM2712 and rebooted and now it seems unlocked again. Is that normal?
A: Yes, BCM2712 OTP locks are temporary and must be reapplied on every boot.

# Making customer OTP bits unreadable on non-BCM2712 devices

Q: Can I stop anyone from even reading my customer OTP bits?
A: Yes, a special vcmailbox argument makes customer OTP bits completely unreadable.

Q: If I make the OTP unreadable, can I reverse that later?
A: No, making OTP bits unreadable is irreversible and permanent.

# Customer MAC addresses on BCM2712 devices

Q: Can I set a custom MAC address on my BCM2712 Pi?
A: Yes, you can set custom Ethernet, Wi-Fi, and Bluetooth MAC addresses in OTP.

Q: How do I read the current Wi-Fi MAC address stored in OTP on a BCM2712?
A: Use vcmailbox tag `0x00030083` with six-byte request and response sizes.

Q: I'm trying to set a MAC address but I'm not sure if it's formatted right. How do I check?
A: Run the check command then look at vclog to verify the MAC address format.

Q: Are there any MAC addresses that aren't allowed when setting a custom one?
A: Multicast addresses are invalid; avoid setting the least significant bit of the first octet.

Q: What happens if I set a customer MAC address to all F's?
A: A MAC address of `ff:ff:ff:ff:ff:ff` is ignored entirely.

# Device-specific private key

Q: Can I use my Raspberry Pi to store an encryption key?
A: Yes, OTP rows are available for storing a device-specific private key.

Q: How many bits of private key storage do I get on a BCM2712 versus an older Pi?
A: BCM2712 devices get 512 bits; non-BCM2712 devices get 256 bits of key storage.

Q: Who's allowed to read the private key rows on Raspberry Pi OS?
A: Only users in the `video` group can access `/dev/vcio` to read private key rows.

Q: Does the Raspberry Pi have a secure hardware place to store encryption keys?
A: No, Raspberry Pi computers do not have a hardware protected key store.

Q: Can I use the private key rows for something other than encryption if I don't need secure boot?
A: Yes, if encryption isn't needed, private key rows can store general-purpose information.

# Program a key into OTP with rpi-otp-private-key

Q: Which Raspberry Pi models work with the rpi-otp-private-key script?
A: The script only works on devices using BCM2711 or BCM2712 processors.

Q: How do I read the private key that's stored in OTP?
A: Run `rpi-otp-private-key` from the usbboot tools directory to get a hex output.

Q: I want to write a random key to OTP. How do I generate and store one?
A: Run `rpi-otp-private-key -w $(openssl rand -hex 32)` to write a random key.

Q: Can I write just part of the key storage instead of the whole thing?
A: Yes, use `-l` for word count and `-o` for a start offset within the key store.

# Mailbox API for reading/writing the key

Q: How do I read all the private key rows using vcmailbox directly?
A: Use vcmailbox tag `0x00030081` with 40-byte request and response sizes.

Q: How do I write a key directly using vcmailbox instead of the script?
A: Use vcmailbox tag `0x00038081` with 40 bytes and your key data replacing the zeros.
