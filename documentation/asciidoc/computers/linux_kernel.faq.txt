# Introduction

Q: Where does Raspberry Pi keep its kernel source code?
A: The Raspberry Pi kernel is hosted on GitHub at raspberrypi/linux.

Q: Does the Pi kernel always match the latest Linux kernel?
A: No, updates lag behind upstream Linux; Raspberry Pi integrates long-term releases.

Q: How does Raspberry Pi decide when to update the main kernel branch?
A: After extensive testing and discussion, they merge the next branch into main.

# Update

Q: My Pi's kernel seems outdated. Does it update automatically or do I have to do something?
A: The normal Raspberry Pi OS update process automatically updates your kernel.

Q: I want to try a newer kernel that's not fully stable yet. How do I get that?
A: You can manually update to the latest unstable test kernel using rpi-update.

# Build the kernel

Q: What's the difference between a native build and cross-compilation? I keep seeing both terms.
A: Native builds compile on the target device; cross-compilation builds for a different target.

Q: Can I build a 64-bit kernel from my 32-bit Pi?
A: Yes, cross-compilation lets you build a 64-bit kernel from a 32-bit OS.

# Download kernel source

Q: I want to build the kernel but I don't know where to start. What do I need first?
A: First install Git, then clone the Raspberry Pi kernel source from GitHub.

Q: The git clone is taking forever. Is there a faster way to just grab what I need?
A: Use the --depth=1 flag to download only the current branch without full history.

Q: I want a specific branch of the kernel, not just the default one. How do I do that?
A: Add --branch and the branch name to the git clone command with --depth=1.

# Natively build a kernel

Q: I'm building the kernel right on my Pi. What packages do I need to install first?
A: Install bc, bison, flex, libssl-dev, and make as build dependencies.

Q: I've got a Pi 4 and I want to build a 64-bit kernel natively. What commands do I run?
A: Set KERNEL=kernel8 and run make bcm2711_defconfig inside the linux directory.

Q: What command do I use to build a 64-bit kernel natively?
A: Run make -j6 Image.gz modules dtbs to build a 64-bit kernel.

Q: Building the kernel is so slow on my Pi. Is there anything I can do to speed it up?
A: Use make -j with 1.5 times your processor count to use multiple cores.

Q: How do I find out how many processors my Pi has for the make command?
A: Run nproc to see how many processors your device has.

# Customise the kernel version using `LOCALVERSION`

Q: I built my own kernel and now it's overwriting my existing modules. How do I stop that?
A: Adjust LOCALVERSION in .config to give your custom kernel a unique version name.

Q: I want to see my custom kernel name when I run uname. How do I set that up?
A: Change the CONFIG_LOCALVERSION line in .config to include your custom name.

# Install the kernel

Q: I've compiled the kernel. Now how do I actually get it onto my Pi?
A: Install modules with modules_install, then copy kernel image and device tree blobs to boot.

Q: Should I back up my old kernel before installing the new one I compiled?
A: Yes, copy the existing kernel image to a backup file before installing the new one.

Q: I don't want to overwrite my working kernel in case my new one breaks. Is there another way?
A: Copy the kernel with a different filename and set the kernel= entry in config.txt.

Q: After installing my compiled kernel, how do I actually boot into it?
A: Run sudo reboot to restart and load the freshly-compiled kernel.

# Cross-compile the kernel

Q: I want to cross-compile on my laptop. What do I need to install?
A: Install bc, bison, flex, libssl-dev, make, libc6-dev, libncurses5-dev, and a toolchain.

Q: I'm cross-compiling a 64-bit kernel. Which toolchain package do I need?
A: Install crossbuild-essential-arm64 for building a 64-bit kernel.

Q: Which Linux distro should I use as my cross-compilation host?
A: Ubuntu is recommended since compilation commands are similar to Raspberry Pi OS.

# Install the kernel (cross-compile)

Q: I've cross-compiled my kernel. How do I find out which device is my SD card?
A: Run lsblk before and after inserting the SD card to identify the new device.

Q: After cross-compiling, how do I mount the SD card to copy the kernel over?
A: Mount the FAT32 partition to mnt/boot and root partition to mnt/root.

# Configure the kernel

Q: I want to change some kernel settings. What's the easiest way to do that?
A: Use the make menuconfig interface to configure kernel options graphically.

Q: How do I navigate around in menuconfig? I can't figure out the controls.
A: Use arrow keys to navigate, Enter to enter submenus, and Escape twice to go back.

Q: I'm in menuconfig and I want to toggle something on or off. How do I do that?
A: Press the space bar to toggle the state of a binary option.

Q: I keep accidentally breaking my kernel config. Any advice for beginners?
A: Start small and get comfortable with the process before enabling or disabling many things.

Q: Where does menuconfig save my changes when I'm done?
A: By default it saves to the .config file in the kernel source directory.

Q: I need to install menuconfig but I'm missing something. What package do I need?
A: Install libncurses5-dev to get the headers menuconfig needs to compile.

# Patch the kernel

Q: How do I check which version of the kernel I'm currently running?
A: Run uname -r to see the kernel version currently running on your device.

Q: Why would I even want to patch the kernel? What's that useful for?
A: Patches can support new hardware or enable features like a fully pre-emptible real-time kernel.

Q: I've got a patch file downloaded. How do I actually apply it?
A: Use the patch utility with cat patch-file | patch -p1 to apply it.

Q: What if the patches I got are a whole folder of files instead of one file?
A: If patches are in mailbox format, use git am to apply the whole folder at once.

# Kernel headers

Q: I'm trying to compile a kernel module and it's failing. Do I need the kernel headers?
A: Yes, kernel headers provide function and structure definitions needed to compile modules.

Q: What's the easiest way to get kernel headers on a 64-bit Raspberry Pi OS?
A: Run sudo apt install linux-headers-rpi-v8 to install the headers.

Q: I installed the kernel headers but nothing seemed to happen. Is that normal?
A: Yes, installation can take several minutes with no progress indicator shown.

Q: My Pi just got a new kernel. Will the apt kernel headers package match it right away?
A: No, it can take several weeks for the apt package to reflect the latest kernel version.

# Contribute

Q: I fixed a bug that's specific to the Raspberry Pi. Where do I send that?
A: Submit a pull request to the Raspberry Pi kernel repository on GitHub.

Q: I wrote a new Linux driver that works on any system, not just Pi. Where does that go?
A: Submit it to the upstream Linux kernel first, then it'll eventually reach the Pi kernel.

Q: How do I submit changes to the Linux kernel? Is it through GitHub like the Pi kernel?
A: No, Linux kernel development happens on mailing lists, not GitHub; submit changes as patches.

Q: I submitted a change to the upstream Linux kernel. Will it automatically get into the Pi kernel?
A: Once tested for compatibility with the Raspberry Pi kernel, your changes reach a stable release.

# Whole Document

Q: I just got a Pi and I want to try building my own kernel. Where do I even begin?
A: Install Git, clone the kernel source, install build dependencies, then configure and build.

Q: Can I build a kernel for my Pi 5 the same way as for a Pi 4?
A: No, Pi 5 uses kernel_2712 and bcm2712_defconfig, while Pi 4 uses different settings.

Q: I'm nervous about messing up my working kernel. Is there a safe way to test a custom one?
A: Save the kernel with a different filename and select it in config.txt, keeping the original safe.
