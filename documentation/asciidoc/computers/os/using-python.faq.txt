# Use Python on a Raspberry Pi

Q: I heard I shouldn't mess with the system Python. What should I use instead to install libraries?
A: Use apt for system packages or pip inside a Python virtual environment.

Q: My Pi came with Python already, right? I didn't need to install it?
A: Yes, Raspberry Pi OS comes with Python 3 pre-installed by default.

Q: What are the two ways I can install Python stuff on my Pi?
A: Use apt for pre-configured packages or pip inside a virtual environment.

# Install Python packages using `apt`

Q: Why would I use apt instead of pip to install Python stuff?
A: Apt packages are pre-compiled, install faster, and handle all dependencies automatically.

Q: I want to install numpy on my Pi. What's it called in apt?
A: The numpy package is available via apt as python3-numpy.

Q: How do I find Python packages I can install with apt?
A: Use the apt search command; Python packages usually have a python3- prefix.

Q: I'm worried uninstalling a package will break other things. Does apt help with that?
A: Yes, apt ensures uninstalling packages won't break your other installed packages.

# Install Python libraries using `pip`

Q: I tried doing pip install and got some weird error about externally managed environment. What's going on?
A: Since Bookworm, pip can only install into a virtual environment, not system-wide.

Q: I just want to install a library for everyone on the system. How do I do that?
A: Install it system-wide using apt instead of pip.

Q: Wait, who actually decided pip couldn't install system-wide anymore — was that Raspberry Pi?
A: No, that change was introduced by the Python community, not Raspberry Pi.

Q: What even causes conflicts between apt and pip? Why does this matter?
A: They conflict over Python API incompatibilities and file ownership of installed packages.

# Use `pip` with virtual environments

Q: How do I actually create a virtual environment for my project?
A: Run python -m venv env from your project's root folder to create one.

Q: I made a virtual environment but how do I actually start using it?
A: Run source env/bin/activate from your project root to enter it.

Q: I'm done working. How do I get out of the virtual environment?
A: Run the deactivate command from any directory to exit the virtual environment.

Q: Should I make a separate virtual environment for every single project or just one for everything?
A: You can do either — per-project environments or one shared per-user environment both work.

Q: I want one virtual environment for my whole user account, not per project. How do I set that up?
A: Run python -m venv ~/.env to create a hidden shared environment in your home directory.

# Create a virtual environment

Q: I want my virtual environment to already have all my system Python packages in it. Is there a way to do that?
A: Pass the --system-site-packages flag when creating the virtual environment.

# Enter a virtual environment

Q: How do I know if I'm actually inside a virtual environment or not?
A: Your prompt shows the environment name in parentheses when you're inside one.

Q: I'm inside my virtual environment but I want to double-check what's installed. How do I do that?
A: Run pip list to see installed packages; the list will be much shorter than system Python's.

Q: If I install something with pip while I'm in a virtual environment, does it affect the rest of my system?
A: No, packages installed inside a virtual environment only affect that specific environment.

# Exit a virtual environment

Q: What's the command to leave a virtual environment when I'm done?
A: Run deactivate from any directory to exit the virtual environment.

# Use the Thonny editor

Q: What code editor do they recommend for Python on the Pi?
A: Raspberry Pi recommends Thonny for editing Python code on the Raspberry Pi.

Q: I'm using Thonny but I want it to use my virtual environment instead of system Python. How do I switch?
A: Click the interpreter menu in Thonny's bottom right corner and select your environment.

Q: Thonny keeps using system Python but I want my venv. Where's the setting for that?
A: Use the interpreter menu bottom right in Thonny, then choose Configure interpreter.
