# `start_x`, `start_debug`

Q: What does setting start_x equals one actually do under the hood?
A: It sets start_file to start_x.elf and fixup_file to fixup_x.dat.

Q: I'm on a Pi 4 and used start_x equals one but it's using different files than expected. Why?
A: Pi 4 uses start4x.elf and fixup4x.dat if those files are present.

Q: What firmware files does start_debug equals one load?
A: It loads start_db.elf and fixup_db.dat as the firmware files.

# `disable_commandline_tags`

Q: How do I stop start.elf from filling in ATAGS before the kernel launches?
A: Set disable_commandline_tags to 1 to stop that from happening.

# `arm_control`

Q: I saw arm_control in some old config. Should I still be using it?
A: No, it's deprecated; use arm_64bit instead to enable 64-bit kernels.

# `arm_peri_high`

Q: How do I turn on high peripheral mode on my Pi 4?
A: Set arm_peri_high to 1, though it's set automatically with a suitable DTB.

Q: What happens if I enable high peripheral mode without the right device tree?
A: Your system will fail to boot without a compatible Device Tree loaded.

# `kernel_address`

Q: Where in memory does the Pi load the kernel by default?
A: 32-bit kernels load at 0x8000 and 64-bit kernels at 0x200000 by default.

Q: If I set kernel_old, where does the kernel get loaded?
A: With kernel_old set, kernels are loaded to memory address 0x0.

# `kernel_old`

Q: I want my kernel loaded at address zero. What do I set?
A: Set kernel_old to 1 to load the kernel to memory address 0x0.

# `init_uart_baud`

Q: What's the default baud rate for the UART on a Raspberry Pi?
A: The default initial UART baud rate is 115200.

# `init_uart_clock`

Q: What's the default UART clock frequency and does it affect all UARTs?
A: Default is 48 MHz, but it only applies to UART0, not UART1.

Q: What's the max baud rate I can actually get from the UART?
A: Maximum UART baudrate is limited to one-sixteenth of the clock frequency.

Q: I'm using a Pi 3 and wondering which UART it defaults to.
A: Pi 3's default UART is UART1, running off the core VPU clock.

# `bootcode_delay`

Q: My monitor sometimes doesn't get detected properly on first boot but works after a reboot. Any fix?
A: Try setting bootcode_delay to add seconds before reading the monitor's EDID.

Q: What does bootcode_delay actually do and what's its default?
A: It delays bootcode.bin before loading start.elf; default value is zero.

# `boot_delay`

Q: My SD card takes a while to get ready and Linux won't boot reliably. What can I do?
A: Set boot_delay to force start.elf to wait before loading the kernel.

Q: How do I calculate the total boot delay if I'm using both boot_delay and boot_delay_ms?
A: Total milliseconds equals 1000 times boot_delay plus boot_delay_ms combined.

# `boot_delay_ms`

Q: What's the difference between boot_delay and boot_delay_ms?
A: boot_delay_ms adds milliseconds of delay, working together with boot_delay.

# `enable_gic` (Raspberry Pi 4 Only)

Q: Can I use the old legacy interrupt controller on my Pi 4B instead of the GIC?
A: Yes, set enable_gic to 0 to route interrupts via the legacy interrupt controller.

Q: What's the default for enable_gic on the Pi 4?
A: The default value for enable_gic on Raspberry Pi 4B is 1.

# `upstream_kernel`

Q: What does upstream_kernel equals one actually change about how things load?
A: It sets os_prefix to upstream/ and prefers upstream Linux DTB filenames.

Q: If the upstream DTB file isn't found, does everything just break?
A: No, firmware loads the downstream variant and automatically applies the upstream overlay.

# Whole Document

Q: These settings all look really old. Are they still the right ones to use?
A: They're legacy boot options; config.txt boot options are also available for reference.

Q: I'm trying to add a delay before my Pi boots. What options do I have?
A: You can use bootcode_delay, boot_delay, and boot_delay_ms for different delay stages.

Q: What's the quickest way to pick a firmware configuration on a Raspberry Pi?
A: Use start_x or start_debug, as they're the recommended shortcut methods for firmware configuration.
