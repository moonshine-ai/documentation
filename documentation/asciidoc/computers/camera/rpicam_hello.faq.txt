# `rpicam-hello`

Q: How do I get my Pi camera to show a preview on screen?
A: Run `rpicam-hello` in a terminal to display a five-second preview.

Q: The preview window just closes really fast. How do I keep it open longer?
A: Use `--timeout 0` to keep the preview running indefinitely.

Q: I want the camera preview to stay open for like 10 seconds. How do I set that?
A: Pass the `--timeout` option with a duration value in milliseconds.

Q: How do I close the camera preview once it's running?
A: Press Ctrl+C in the terminal or click the preview window's close button.

# Display an image sensor preview

Q: I'm using SSH with X forwarding and the camera preview isn't working. What's going on?
A: Zero-copy GPU buffer sharing means X forwarding is not supported by default.

Q: I want to use X forwarding for the preview. Is there any workaround?
A: Pass the `--qt-preview` flag to render the preview in a Qt window instead.

Q: The Qt preview is working but it feels sluggish. Is that normal?
A: Yes, the Qt preview window uses more resources than the other preview options.

Q: I don't want any preview window at all. How do I just run the camera without showing anything?
A: Pass the `-n` or `--nopreview` flag to suppress the preview window entirely.

Q: Can I show camera info like gain values in the preview window title?
A: Yes, use `--info-text` with percent directives like `%rg` and `%bg`.

Q: I'm getting some Glib-GObject errors and the Qt preview won't show up. What do I do?
A: Edit `/etc/xdg/qt5ct/qt5ct.conf` as root and replace `style=gtk2` with `style=gtk3`.

Q: I don't have a desktop running. Will the camera preview still show up somehow?
A: Yes, without a desktop the preview draws directly to the display using Linux DRM.
