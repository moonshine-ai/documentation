# Post-processing with `rpicam-apps`

Q: What's post-processing in rpicam-apps and do I actually need it?
A: It passes camera images through custom processing and analysis stages you configure.

Q: How do I tell rpicam-hello to use a post-processing stage?
A: Pass a JSON file to the `--post-process-file` option when running the command.

Q: Where can I find example JSON files for the built-in post-processing stages?
A: They're in the assets folder of the rpicam-apps repository on GitHub.

Q: I want to run two post-processing stages one after the other. Can I do that?
A: Yes, put multiple stages as top-level keys in a single JSON file.

Q: Do post-processing stages only change the image, or can they do other stuff too?
A: Some alter the image, others analyse it and generate metadata passed to other stages.

Q: I heard OpenCV stages don't work on the default Raspberry Pi OS install. Is that true?
A: Yes, OpenCV and TensorFlow Lite stages are disabled unless you recompile rpicam-apps yourself.

Q: I'm on a Pi 3 running 32-bit and want to recompile rpicam-apps. Is there anything special I should do?
A: Compile with `-DENABLE_COMPILE_FLAGS_FOR_TARGET=armv8-neon` to speed up certain stages.

# `negate` stage

Q: What does the negate stage actually do to my photo?
A: It flips light pixels to dark and dark pixels to light, inverting the image.

Q: Can I tweak any settings on the negate stage?
A: No, the negate stage has no user-configurable parameters at all.

Q: What's the simplest way to test the negate stage?
A: Run `rpicam-hello --post-process-file negate.json` with the default negate JSON file.

# `hdr` stage

Q: What's the difference between HDR and DRC in that hdr stage?
A: DRC uses a single frame while HDR combines multiple frames for a similar result.

Q: How long does HDR processing take on a Pi 4?
A: Between two and three seconds for a 12 megapixel image on a Raspberry Pi 4.

Q: I want stronger or weaker HDR processing. What settings should I change?
A: Adjust `global_tonemap_strength` and `local_tonemap_strength` to control processing strength.

Q: If I'm doing HDR with multiple frames, does the app see every frame or just the final result?
A: The stage sends only the final processed image to the application, not individual frames.

Q: How many frames does the default HDR setup use?
A: The default HDR configuration accumulates eight frames.

# `motion_detect` stage

Q: Does motion detection need OpenCV or any other library installed?
A: No, the motion detect stage has no dependencies on third-party libraries.

Q: My motion detection is triggering way too easily. What should I tweak?
A: Adjust the `difference_m`, `difference_c`, and `region_threshold` parameters to reduce sensitivity.

Q: How do I set up the region of interest for motion detection?
A: Set `roi_x`, `roi_y`, `roi_width`, and `roi_height` as proportions between zero and one.

Q: Can I get some console output to see when motion is actually detected?
A: Yes, set the `verbose` parameter to print messages including when motion status changes.

Q: I want motion detection to run faster. Any tips?
A: Use the `hskip` and `vskip` parameters to subsample pixels and improve performance.

Q: What command do I run to try out motion detection?
A: Run `rpicam-hello --lores-width 128 --lores-height 96 --post-process-file motion_detect.json`.

# Whole Document

Q: Do I write my own code for post-processing or is there a simpler way?
A: You supply a JSON file naming which built-in stages and options to apply; no coding needed.

Q: Why does image analysis use a lower resolution feed instead of the full image?
A: Reduced resolution improves performance; rpicam-apps provides a dedicated low-res ISP feed.

Q: I combined Sobel and negate stages. What does that actually look like?
A: Sobel produces bright edges on black, then negate flips it to dark edges on white.
