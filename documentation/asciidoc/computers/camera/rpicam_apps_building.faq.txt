# Build `libcamera` and `rpicam-apps`

Q: Why would I bother building rpicam-apps myself instead of just using the version that came with my Pi?
A: Building yourself gets latest features, better optimisation, and optional OpenCV or TFLite support.

Q: I've got a Pi 3 running a 32-bit OS. Is there any reason to build rpicam-apps from source?
A: Yes, you can compile with extra optimisations specifically for Pi 3 running a 32-bit OS.

# Remove pre-installed `rpicam-apps`

Q: Do I need to uninstall the existing rpicam-apps before I build my own version?
A: Yes, remove it first using sudo apt remove --purge rpicam-apps before installing your own.

Q: What's the command to completely get rid of the pre-installed rpicam-apps?
A: Run sudo apt remove --purge rpicam-apps to fully remove the pre-installed version.

# Building `rpicam-apps` without building `libcamera`

Q: Can I just build rpicam-apps without having to rebuild libcamera from scratch too?
A: Yes, install libcamera and libepoxy via apt instead, then just build rpicam-apps.

Q: I don't need that GLES preview window thing. Do I still have to install libepoxy?
A: No, you can omit libepoxy-dev if you don't need the GLES or EGL preview window.

Q: What do I need to install if I want the Qt preview window when building rpicam-apps?
A: Install qtbase5-dev, libqt5core5a, libqt5gui5, and libqt5widgets5 as additional dependencies.

Q: I want libav support in rpicam-vid. What extra packages do I need?
A: Install libavcodec-dev, libavdevice-dev, libavformat-dev, and libswresample-dev for libav support.

Q: I'm on Raspberry Pi OS Lite and I don't have git. Do I need it to build this stuff?
A: Yes, install git with sudo apt install -y git before building on Raspberry Pi OS Lite.

# Building `libcamera`

Q: When should I actually bother building libcamera from scratch?
A: Only build from scratch if you need custom behaviour or features not yet in apt repositories.

Q: I'm on Raspberry Pi OS Lite and want to build libcamera. What do I need first?
A: Start by installing python3-pip, git, and python3-jinja2 before the other libcamera dependencies.

Q: My Pi has only 1 gig of RAM and the libcamera build keeps crashing. What can I do?
A: Append -j 1 to ninja commands to limit the build to a single process and save memory.

Q: I just built libcamera. Can I use my old rpicam-apps with it, or do I have to rebuild that too?
A: Always rebuild rpicam-apps after building libcamera, as libcamera has no stable binary interface.

Q: I don't use GStreamer. Do I still need those glib dependencies when building libcamera?
A: No, disable gstreamer with -Dgstreamer=disabled and skip libglib2.0-dev and libgstreamer-plugins-base1.0-dev.

# Building `rpicam-apps`

Q: I'm on Raspberry Pi OS Lite with no desktop. What meson flags should I use when building rpicam-apps?
A: Disable libav, egl, and qt flags since Lite is headless; keep drm enabled for preview rendering.

Q: How do I check that my Pi is actually using the new rpicam-apps I just built?
A: Run rpicam-still --version and check the output shows your local build's date and time.

Q: After installing my build, rpicam-apps isn't working right. Someone mentioned ldconfig. What's that about?
A: Run sudo ldconfig to update the library cache if you're having trouble accessing your new build.

Q: I've got OpenCV installed and want to use it. What flag do I add when building rpicam-apps?
A: Add -Denable_opencv=enabled to your meson setup command to enable OpenCV post-processing stages.

Q: I want to speed things up on my Pi 3 running 32-bit. Is there a flag for that?
A: Yes, use -Dneon_flags=armv8-neon to enable optimisations for 32-bit OS on Pi 3 or Pi 4.

Q: My Pi Zero keeps running out of memory during the rpicam-apps build. How do I fix that?
A: Append -j 1 to meson commands to limit the build to one process and reduce memory usage.

# `rpicam-apps` meson flag reference

Q: What does the DRM flag actually do when I'm building rpicam-apps?
A: It enables DRM and KMS preview rendering, used as a preview window without a desktop environment.

Q: Why is the Qt preview not recommended even though it's an option?
A: The Qt-based preview is computationally very expensive, though it does work with X display forwarding.

Q: What values can I actually pass to those meson flags when building rpicam-apps?
A: Each flag supports enabled, disabled, or auto, where auto enables if dependencies are available.

Q: I enabled TensorFlow Lite but the build isn't finding it correctly. Any suggestions?
A: You may need to tweak the meson.build file in the post_processing_stages directory for TFLite.

Q: What's the difference between setting a flag to disabled versus auto?
A: Disabled always skips the option; auto enables it only if the required dependencies are available.

# Building `libepoxy`

Q: Do I really need to build libepoxy myself, or can I skip that?
A: Rebuilding libepoxy is normally unnecessary since this library changes only very rarely.

Q: What's the command to actually build libepoxy once I've got everything set up?
A: Run ninja inside the _build directory to build libepoxy after configuring with meson.
