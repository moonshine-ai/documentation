# Use multiple cameras

Q: I've got a Raspberry Pi 5 — can I connect two cameras directly to it?
A: Yes, Pi 5 has dual MIPI connectors for connecting two cameras directly.

Q: I'm using a regular Pi, not a Compute Module. Can I run two cameras at the same time?
A: With a Video Mux board, only one camera can be used at a time.

Q: How do I see what cameras are connected to my Pi?
A: Use the list-cameras option to see all available cameras on your platform.

Q: I've got two cameras plugged in. How do I pick which one to use?
A: Pass the camera index to the camera option to choose which one to use.

Q: Can I sync the 3A settings between two cameras running at the same time?
A: No, libcamera doesn't support that; use external sync or manual mode instead.

# Software Camera Synchronisation

Q: Do I need to solder anything to sync two cameras with software?
A: No soldering or hardware connections are required for software camera synchronisation.

Q: Will software camera sync work with third-party camera modules, not just official ones?
A: Yes, as long as their drivers implement frame duration control correctly.

Q: How does the software camera sync actually work? Like what's happening behind the scenes?
A: One camera is the server broadcasting timing messages; clients adjust frame timing to match.

Q: Can I sync cameras that are on totally different Raspberry Pi boards, not just the same one?
A: Yes, client cameras can be on different Raspberry Pis connected to the same network.

Q: Do both cameras need to be the same model for the sync to work?
A: No, camera models on clients and server can be different, though sync may be less precise.

Q: How accurate is the sync when both cameras are the same model on the same Pi?
A: Frame start times should match within several tens of microseconds in normal operation.

Q: My two cameras are on different Pis. Do I need to worry about clock sync?
A: Yes, system clocks should be synchronised using NTP or a more precise protocol like PTP.

Q: Should I start the client or the server first when doing camera sync?
A: Start clients before the server so they're ready and waiting when the server broadcasts.

Q: How long does the server wait before it decides sync is done and starts recording?
A: By default the server waits 100 frames before reaching the synchronisation point.

Q: Can I have more than one server on the same network doing camera sync?
A: Yes, multiple servers are allowed as long as they broadcast to different network addresses.

Q: I'm using rpicam-vid for sync recording. What command do I run for the client side?
A: Run rpicam-vid with --sync client and it waits until the synchronisation point to record.

Q: What framerate does rpicam-vid use by default when I'm doing synced recording?
A: rpicam-vid defaults to a fixed 30 frames per second.

Q: Why can't I set the framerate to the maximum my camera supports when doing sync?
A: The sync algorithm may need to shorten frames, which fails if the camera's already at maximum.

Q: I'm getting dropped frames during synced recording. What can I do to fix that?
A: Try lowering the framerate, increasing buffer count, or reducing system load.

# Whole Document

Q: I want to run two cameras at the same time on a Compute Module. Is that possible?
A: Yes, you can connect and use two cameras simultaneously on a Compute Module I/O board.

Q: What's the difference between how the server and client behave when the sync point is reached?
A: Both server and client signal the camera application to start using frames at the same moment.
