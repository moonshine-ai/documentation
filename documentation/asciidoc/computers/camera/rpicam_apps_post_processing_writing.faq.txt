# Write your own post-processing stages

Q: Can I use TensorFlow Lite in my own post-processing stage?
A: Yes, derive your class from TfStage to use TensorFlow Lite.

Q: I want to write a custom post-processing stage. Where do I even start?
A: Derive a new class from the PostProcessingStage class to begin.

Q: Do I need to add my custom stage somewhere so the system knows about it?
A: Call RegisterStage to register your stage, and add it to meson.build.

# Basic post-processing stages

Q: My pipeline keeps stuttering. Is my post-processing stage causing that?
A: Process blocks the pipeline; delegate slow algorithms to an asynchronous thread.

Q: I'm doing image analysis and don't need full resolution. Is there a faster way?
A: Use a low-resolution image stream for analysis that doesn't need full resolution.

Q: What format does the low resolution stream use? I need it for OpenCV.
A: Most streams including low resolution use YUV420, which you may need to convert.

Q: I want the best performance when editing images. Any tips?
A: For best performance, always alter images in-place rather than copying them.

Q: What does the Process function actually return and what does it mean?
A: Return true to stop the framework delivering that request to the application.

Q: When does the Configure function get called exactly?
A: Configure is called just after the camera is configured, to allocate resources.

Q: What's the Teardown function for? Is it like a destructor?
A: Teardown is called when camera configuration is destroyed; de-allocate Configure resources there.

Q: I'm worried about thread conflicts when using OpenCV inside post-processing. Should I be?
A: OpenCV can add parallelism within frames; consider serialising calls since post-processing already multithreads.

Q: Is there a simple example stage I can look at to understand how this works?
A: negate_stage.cpp is a basic example negating images in barely half a dozen lines.

Q: What's a good example of using OpenCV in a custom stage?
A: sobel_cv_stage.cpp implements a Sobel filter in just a few OpenCV function lines.

Q: When I delegate work to another thread, do I need to copy the image buffer?
A: Yes, when delegating to another thread you must copy the image buffers.

# TensorFlow Lite stages

Q: I want to make a TFLite stage. Do I still use PostProcessingStage as my base class?
A: No, derive from TfStage instead when building TensorFlow Lite stages.

Q: Does TfStage handle threading automatically so my camera doesn't stutter?
A: Yes, TfStage delegates model execution to a separate thread automatically.

Q: Do I have to implement all the same functions for a TfStage as a regular stage?
A: TfStage implements most functions, but you must still implement Name yourself.

Q: What's the readExtras function for in a TfStage?
A: Use readExtras to read extra parameters and verify the loaded model is correct.

Q: When does interpretOutputs run, and what's it for?
A: interpretOutputs runs in the model's thread when the model completes, to read outputs.

Q: What's the difference between interpretOutputs and applyResults?
A: interpretOutputs reads model output; applyResults applies those results to the current frame.

Q: What does applyResults typically do?
A: applyResults typically attaches metadata or draws results onto the current frame.

Q: Is there a real example of a TFLite stage I can look at?
A: See object_classify_tf_stage.cpp and pose_estimation_tf_stage.cpp for example implementations.

Q: What happens in checkConfiguration for a TFLite stage?
A: Check for required streams; skip processing or throw an error if streams are missing.
