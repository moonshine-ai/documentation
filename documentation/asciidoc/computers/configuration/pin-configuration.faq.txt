# Change the default pin configuration

Q: I heard custom pin configs via Device Tree blobs are going away. Is that true?
A: Yes, custom default pin configurations via user-provided Device Tree blobs are deprecated.

# Device pins during boot sequence

Q: What actually happens to the GPIO pins when my Pi boots up?
A: Pins go through multiple configuration stages, from power-on defaults through kernel setup.

Q: My peripheral isn't behaving right during boot. What's going on?
A: GPIO pins may not be in the expected state until the full boot sequence completes.

Q: I've got a peripheral that freaks out during boot because the pin state is wrong. What can I do about it?
A: Choose a pin with correct default pulls, delay startup, or add a pull-up or pull-down resistor.

Q: Does a soft reset treat the GPIO pins the same way as a full power-on?
A: Soft reset follows the same procedure, except default pulls only apply on power-on reset.

Q: How long does it take for all the GPIO pin setup stuff to finish during boot?
A: The process may take a few seconds to complete during bootup.

# Provide a custom Device Tree blob

Q: How do I compile a dot dts file into a dot dtb file?
A: Install device-tree-compiler and use the dtc command to compile the source file.

Q: What package do I need to install to compile Device Tree source files?
A: Run sudo apt install device-tree-compiler to get the dtc tool.

Q: Can I go the other way and convert a dtb file back to a dts file?
A: Yes, use dtc with the -I dtb and -O dts flags to convert it back.

Q: Where does the compiled dt-blob.bin file need to go?
A: The output file goes to /boot/firmware/dt-blob.bin on your Pi.

# Sections of the `dt-blob`

Q: What's dt-blob.bin actually used for? Does Linux use it?
A: It configures the VideoCore binary blob at boot time; Linux kernel doesn't currently use it.

Q: Can one dt-blob file work across different Pi models including Compute Modules?
A: Yes, dt-blob can configure all Raspberry Pi versions including Compute Modules.

Q: What are the main sections you'd put inside a dt-blob file?
A: The main sections are videocore, pins_*, pin_config, pin_defines, and pin at pinname.

Q: I've got a Pi 3 Model B+. What's the pins section called for my board?
A: Use the pins_3bplus section for the Raspberry Pi 3 Model B+.

Q: I'm using a Raspberry Pi Zero W. Which pins section do I use in the blob file?
A: Use the pins_pi0w section for the Raspberry Pi Zero W.

Q: What's the difference between pins_rev1 and pins_rev2?
A: Rev1 has moved I2C pins; Rev2 adds codec pins on P5.

Q: I want to set a default for any pin I haven't specifically named. How do I do that?
A: Use the pin@default section inside pin_config for unnamed pins.

Q: What kinds of things can I actually configure for an individual pin?
A: You can set polarity, termination, startup state, function, and drive strength.

Q: What drive strength values are valid for pins in the blob file?
A: Only 8 mA and 16 mA are valid drive strength values.

Q: Can I set different drive strengths for individual pins in a bank?
A: No, you can only specify a single drive strength for the whole bank.

Q: What functions can I assign to a pin in the dt-blob?
A: Functions include input, output, sdcard, i2c, spi, uart, pwm, pcm, dpi, and others.

Q: What's the pin_defines section for? What kind of stuff goes in there?
A: It maps VideoCore functionality like camera power enable or HDMI hotplug to specific pins.

Q: Can I move which pin controls the HDMI hotplug using the dt-blob?
A: Yes, pin_defines lets you move the HDMI hotplug position to a different pin.

# Clock configuration

Q: Can I change the clock settings through the dt-blob file?
A: Yes, but clock configuration is very complex and results can be hard to predict.

Q: How many PLLs does the Pi's clocking system have?
A: There are five separate PLLs, each with its own VCO frequency.

Q: I need to give my audio codec exactly 12288000 Hz. Can the Pi do that?
A: Yes, the example configuration sets GPCLK0 to 12288000Hz for 48000 range audio codecs.

Q: What's the valid frequency range for PLLA's VCO?
A: PLLA's VCO supports frequencies between 600 MHz and 2.4 GHz.

# Whole Document

Q: I just want to understand the big picture. What is dt-blob.bin and why would I need it?
A: It configures VideoCore GPIO pin states and functionality at boot before Linux takes over.
