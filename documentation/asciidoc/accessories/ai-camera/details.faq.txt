# Overview

Q: So how is the AI camera different from just plugging in a regular camera and doing AI on the Pi itself?
A: The IMX500 does AI inference inside the camera, sending only results to the Pi.

Q: What's an input tensor? I keep seeing that term and I don't really get it.
A: It's the portion of the sensor image fed into the AI engine for inferencing.

Q: Can I actually see the input tensor in my app, or is it hidden?
A: It's normally unavailable to apps, but accessible for debugging purposes.

Q: What's a Region of Interest and why would I care about it?
A: It specifies which part of the sensor image gets cropped before neural network processing.

Q: If I don't set a Region of Interest, does it just use the whole image?
A: Yes, the default ROI uses the full image from the sensor, cropping nothing.

Q: What units does the Region of Interest use when I'm setting it?
A: It always uses pixels in the full resolution sensor output.

Q: So the output tensors are just whatever the neural network spits out?
A: Yes, output tensors are inferencing results whose number and shape depend on the network.

# System architecture

Q: Does the AI camera only do inference, or does it also give me a regular image stream?
A: The IMX500 generates both an image stream and an inference stream simultaneously.

Q: When does the camera load the neural network — like, is it at startup or later?
A: The IMX500 loads firmware for a neural network model at startup.

# Device drivers

Q: How does the camera module actually communicate with the Raspberry Pi at a low level?
A: The IMX500 kernel driver configures the camera module over the I2C bus.

Q: Is the firmware loading the same on Pi 5 as on other Pis?
A: Pi 5 uses a custom high speed protocol; other Pis use standard I2C protocol.

Q: Does it have to re-upload the whole firmware every single time I use it?
A: No, the RP2040 caches firmware files, significantly speeding up repeated firmware loading.

Q: What's the RP2040 doing in all of this? I thought that was a microcontroller.
A: It bridges I2C transfers from the kernel to the IMX500 via a SPI bus.

# `libcamera`

Q: How do I get the output tensors from libcamera in my app?
A: They're packaged as Raspberry Pi vendor-specific libcamera controls you can retrieve.

Q: What libcamera controls does the AI camera give me?
A: It provides CnnOutputTensor, CnnInputTensor, CnnOutputTensorInfo, and CnnInputTensorInfo controls.

Q: What's in the CnnInputTensorInfo structure exactly?
A: It contains the network name, width, height, and number of channels.

# `rpicam-apps`

Q: I want to write my own post-processing stage for a neural network. Where do I start?
A: Derive your stage from the IMX500PostProcessingStage base class in rpicam-apps.

Q: When does the Process function actually get called for each frame?
A: Process is called for every frame received by the application.

Q: How do I grab the output tensor inside my Process function?
A: Fetch it from completed_request metadata using the CnnOutputTensor control.

Q: Is there a helper that automatically figures out the right crop for my network's aspect ratio?
A: Yes, SetInferenceRoiAuto automatically calculates the ROI to preserve the input tensor aspect ratio.

Q: How do I show a loading bar while the neural network firmware uploads?
A: Call ShowFwProgressBar to display a progress bar on the console during upload.

Q: I'm getting coordinates from the output tensor but they don't match my image. What's going on?
A: Use ConvertInferenceCoordinates to convert tensor coordinates to ISP output image space.

# Picamera2

Q: Can I use the AI camera with Python, or is it only the C++ stuff?
A: Picamera2 has an IMX500 helper class providing the same functionality as rpicam-apps.

Q: How do I import the IMX500 class in my Python script?
A: Use from picamera2.devices.imx500 import IMX500, then instantiate before Picamera2.

Q: Does the Picamera2 example do any filtering on detections between frames?
A: No, the Picamera2 example applies no additional hysteresis or temporal filtering.

Q: How do I get the output tensors in Picamera2?
A: Call imx500.get_outputs with the request metadata to retrieve output tensors.

Q: I need to convert bounding box coordinates from the tensor to the actual image. How?
A: Use imx500.convert_inference_coords with the coordinates, metadata, and Picamera2 object.

Q: Can I check how the camera is performing frame by frame in Picamera2?
A: Yes, IMX500.get_kpi_info returns frame-level performance indicators for given image metadata.

Q: How do I set the region of interest in Picamera2?
A: Call set_inference_roi_abs with an x_offset, y_offset, width, height tuple in full sensor pixels.

Q: What if I want the ROI to exactly match my neural network's input size?
A: Call imx500.set_inference_aspect_ratio passing imx500.get_input_size() as the argument.

# Whole Document

Q: So basically the AI is running on the camera itself and not on the Pi at all?
A: Correct, the IMX500 runs inference internally so the Pi CPU handles no neural network processing.

Q: Do I need to know C++ to use the AI camera, or can I just use Python?
A: Both are supported; rpicam-apps uses C++ while Picamera2 provides a Python interface.

Q: I just got the AI camera. What are the main concepts I need to understand first?
A: You need to understand input tensors, output tensors, and Region of Interest concepts.
